# Amendment — E15-S4 carries the two new observability criteria

**Amendment id:** `e15-s4-observability-contract`
**Date:** 2026-09-14
**Trigger:** the `/gate --group A` review asked for two acceptance criteria that
did not exist — a request-duration metric (so the declared 500 ms runtime SLO is
measurable rather than always null) and log/metrics input sanitisation (so hostile
input cannot forge a log entry or a counter series). Both were approved.

Only `component-map.md` changes here. The design receipt was re-recorded and the
plan re-sealed.

## Why a new story rather than two more criteria on E15-S1

The obvious placement was E15-S1, which owns the logging and metrics surface.
That was attempted and reverted.

E15-S1 is the **first** story in `specs/stories/story-traces.json`, and
`test-plan-write.js:85` iterates that array in order with no sort, numbering the
verification matrix outward from the first story's criteria. Inserting two
criteria there shifted every later `VM-` id by two. Measured with the change in
place:

| id | matrix said | `test-plan.md` still claimed |
|---|---|---|
| VM-012 | E9-S1-AC2 | E1-S1-AC1 |
| VM-014 | E1-S1-AC1 | E1-S1-AC3 |
| VM-105 | E17-S1-AC2 | E15-S3-AC1 |

All 13 `sprint-contracts/*.json` are frozen against the old ids, and
`test-plan.md` is deliberately *not* regenerated by `test-plan-write --force`
(only `--reset-plan` rewrites a filled plan), so it went stale silently. The
combination is a vacuous-verification hazard: a frozen check reporting PASS for a
criterion it is no longer testing.

**E15-S4 appended last** takes VM-108 and VM-109 and leaves VM-001..107
byte-identical — verified, along with all 13 frozen contracts being unchanged
after re-freezing. Neither new criterion carries an `api` or `e2e` layer, so
neither becomes an evaluator check and no sprint contract gains a row.

The cost is that E15's observability concerns now span two stories. That is the
cheaper trade: the alternative was re-filling all 84 `Observe` cells of the
reviewed reference surface and re-freezing every contract, to move two criteria
that trace to the same story anyway.

## Changes

1. **E15-S4 owns** `backend/tests/architecture/test_observability_contract.py`.
   The story adds no production file of its own: the behaviour deepens two files
   E15-S1 already owns.

2. **Modifies row E15-S1 → E15-S4** covering the correlation middleware and the
   platform routes. The histogram has to be timed where the request is timed and
   rendered where the exposition is rendered, and E15-S1 owns both. This is the
   tracer-then-deepening pattern the table exists to record, and without the row
   `ownership-check` would block every E15-S4 commit.

## Not amended

`api-contracts.md` stays untouched. The `/metrics` auth question is a separate,
approved change awaiting its own amendment, and it cannot be implemented until an
auth layer exists (E1-S1, group B) — E15-S4's Scope Out says so explicitly rather
than leaving it implied.
