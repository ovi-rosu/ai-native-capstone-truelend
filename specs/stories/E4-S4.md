## User Story
As an underwriting lead, I want submissions below a product's minimum income refused at intake so that ineligible applications never enter the underwriting queue.

## Business Value
Keeps the underwriter queue free of applications that policy already excludes, and tells the applicant which threshold they missed.

## Description
Adds the FR-05 intake guard: when declared income is below the selected product's minimum income threshold, submission fails with PolicyViolationException naming the breached threshold, and no application row is persisted.

## Scope
**In:** Minimum-income guard on the submit path; PolicyViolationException error contract naming the breached threshold; Transactional rollback so no application row survives
**Out:** must not persist a partial application row on a refused submission; must not hardcode the minimum income value outside the policy version; must not charge a fee or penalty for a refused submission

## Acceptance Criteria
- **E4-S4-AC1** — *Given* declared income below the selected product's minimum income threshold, *when* the application is submitted, *then* the error response identifies PolicyViolationException.
- **E4-S4-AC2** — *Given* that refused submission, *when* the error body is inspected, *then* it names the breached threshold and the configured value it was checked against.
- **E4-S4-AC3** — *Given* that refused submission, *when* the application table is queried afterwards, *then* no application row was persisted for it.
