## User Story
As a platform operator, I want every request to emit structured, correlated, PII-free logs and a health probe so that I can diagnose the origination flow without leaking applicant identifiers.

## Business Value
Removes the retrofit pass that would otherwise have to revisit every handler written before observability existed, and keeps synthetic PAN, Aadhaar and salary content out of operational logs.

## Description
Installs the platform logging substrate before any other epic emits a log line: JSON formatter, correlation-id middleware that honours or generates X-Request-ID, a redaction filter on every configured logger, and the /health endpoint. D12 places this first in M1 because NFR-03 and NFR-06 are retrofit-hostile.

## Scope
**In:** JSON log formatter, correlation-id middleware and redaction filter registered in the app factory; GET /health returning a JSON readiness body; Log-capture test harness reused by later stories
**Out:** must not add any business endpoint beyond /health; must not write applicant PAN, Aadhaar or salary-document content to any log sink; must not introduce an external log-shipping provider or credentials

## Acceptance Criteria
- **E15-S1-AC1** — *Given* an application payload carrying synthetic PAN, Aadhaar and salary-document content, *when* the request is served and every emitted log record is captured, *then* the captured buffer contains 0 occurrences of each of those three values.
- **E15-S1-AC2** — *Given* the application's logging configuration, *when* every configured logger is enumerated, *then* the redaction filter is installed on 100% of them and a logger registered without it fails the assertion.
- **E15-S1-AC3** — *Given* a request carrying the header X-Request-ID with value req-abc, *when* every log line emitted while serving that request is parsed, *then* 100% of the lines parse as JSON and each carries request_id equal to req-abc.
- **E15-S1-AC4** — *Given* a request with no X-Request-ID header, *when* the response is returned, *then* every request-scoped log line carries the same generated non-empty request_id and the response echoes that id.
- **E15-S1-AC5** — *Given* the backend reporting a successful startup, *when* GET /health is called, *then* the response is 200 with a JSON body and the measured response time is under 1 second.

### Operations
1. Add base runtime settings (log level, service name) to `backend/src/config/settings.py` (new) via a Pydantic `BaseSettings` model.
2. Define `JSONLogFormatter` and a `RedactionFilter` (drops PAN/Aadhaar/salary-document values) and a `configure_logging()` entry point in `backend/src/config/logging.py` (new); install the filter on every configured logger.
3. Define typed error classes (`AppError` and subclasses) in `backend/src/types/errors.py` (new) for the single API-boundary error mapping.
4. Define `CorrelationIdMiddleware` in `backend/src/api/middleware.py` (new): honour inbound `X-Request-ID`, else generate one, bind it to a contextvar for the request scope, and echo it on the response header.
5. Define the global exception handler(s) mapping `AppError` subclasses to JSON responses in `backend/src/api/errors.py` (new).
6. Define `GET /health` in `backend/src/api/platform/routes.py` (new), returning a 200 JSON readiness body.
7. Wire `configure_logging()`, `CorrelationIdMiddleware`, the exception handlers and the platform router into the app factory `create_app()` in `backend/src/api/app.py` (new); expose a module-level `app = create_app()` importable by `uv run uvicorn`.
8. Add shared pytest fixtures — a `TestClient` fixture and a log-capture fixture that installs a handler on the root logger — in `backend/tests/conftest.py` (new).
9. Add redaction, correlation-id and `/health` tests in `backend/tests/unit/test_log_redaction.py` (new), covering AC1-AC5.
