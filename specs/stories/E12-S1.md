## User Story
As a portfolio manager, I want a repeatable end-of-day recalculation for a given date so that a rerun after a failure cannot change the book.

## Business Value
Makes the nightly delinquency refresh safe to rerun, which is what allows an operator to recover from a partial failure without reconciliation work.

## Description
The FR-14 end-of-day operation, parameterised by an as-of date and idempotent by construction. Per D10 it depends on the published bucket ladder and on schedule installment data, not on the repayment posting endpoint, so it can be built and tested against seeded loans in parallel with E11-S2's API work.

## Scope
**In:** As-of-date parameterised end-of-day operation over all active loans; Bucket assignment through the published ladder; Idempotence proof by a second run for the same date
**Out:** must not charge a late fee, penal interest or create a collections record; must not depend on the repayment posting endpoint, per D10; must not change any row on a second run for the same as-of date

## Acceptance Criteria
- **E12-S1-AC1** — *Given* seeded active loans with differing days past due, *when* the end-of-day operation runs for a given as-of date, *then* each loan's stored bucket matches its days past due at that date.
- **E12-S1-AC2** — *Given* a completed end-of-day run, *when* the operation runs a second time for the same as-of date, *then* every bucket and every stored row is byte-identical to the first run's result.
- **E12-S1-AC3** — *Given* an as-of date earlier than a loan's first installment due date, *when* the operation runs for that date, *then* that loan's stored bucket reads CURRENT.
- **E12-S1-AC4** — *Given* the completed run, *when* the loan records are compared against their pre-run state, *then* no fee, penal interest or collections record was created.

### Operations
1. Define `run_end_of_day(as_of_date: date) -> EndOfDayRun` in `backend/src/service/delinquency/end_of_day.py` (new): reads every active loan via `LoanRepository.list_active` (owned by E9-S2); for each loan calls `installment_ladder.ladder_state(loan_id, as_of_date)` (owned by E9-S3) and `classify` in `backend/src/config/delinquency.py` (owned by E11-S1) directly — deliberately never calling E11-S2's repayment-path recalculation, per D-10; writes each loan's recomputed `delinquency_bucket` via `loan_projection.set_projections` (owned by E9-S2, the single projection write path), so a same-input second run overwrites with byte-identical values; appends one `audit_event` via `audit(...)` (owned by E1-S2) recording the invocation; persists no `end_of_day_run` row of its own — `EndOfDayRun` is returned only as a derived response value object.
2. Define `POST /operations/end-of-day` in `backend/src/api/delinquency/end_of_day_routes.py` (new): `require_roles(ADMIN)` per D-N, parses the `as_of_date` request body, calls `end_of_day.run_end_of_day`, and returns the `EndOfDayRun` summary (`as_of_date`, `loans_evaluated`, `buckets`, `completed_at`).
3. Append one `include_router` row for the end-of-day router to the app factory router registry `backend/src/api/app.py` (owned by E15-S1).
4. Add the idempotence integration test in `backend/tests/integration/test_end_of_day_idempotence.py` (new), covering AC1-AC4: seeded active loans with differing days past due each land in the bucket matching their days past due at the given as-of date (AC1); running the operation a second time for the same as-of date leaves every bucket and every stored row byte-identical to the first run (AC2); an as-of date earlier than a loan's first installment due date leaves that loan's bucket at `CURRENT` (AC3); comparing loan records against their pre-run state shows no fee, penal interest or collections record created (AC4).
