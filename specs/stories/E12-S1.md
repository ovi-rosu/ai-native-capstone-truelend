## User Story
As a portfolio manager, I want a repeatable end-of-day recalculation for a given date so that a rerun after a failure cannot change the book.

## Business Value
Makes the nightly delinquency refresh safe to rerun, which is what allows an operator to recover from a partial failure without reconciliation work.

## Description
The FR-14 end-of-day operation, parameterised by an as-of date and idempotent by construction. Per D10 it depends on the published bucket ladder and on schedule installment data, not on the repayment posting endpoint, so it can be built and tested against seeded loans in parallel with E11-S2's API work.

## Scope
**In:** As-of-date parameterised end-of-day operation over all active loans; Bucket assignment through the published ladder; Idempotence proof by a second run for the same date
**Out:** must not charge a late fee, penal interest or create a collections record; must not depend on the repayment posting endpoint, per D10; must not change any row on a second run for the same as-of date

## Acceptance Criteria
- **E12-S1-AC1** — *Given* seeded active loans with differing days past due, *when* the end-of-day operation runs for a given as-of date, *then* each loan's stored bucket matches its days past due at that date.
- **E12-S1-AC2** — *Given* a completed end-of-day run, *when* the operation runs a second time for the same as-of date, *then* every bucket and every stored row is byte-identical to the first run's result.
- **E12-S1-AC3** — *Given* an as-of date earlier than a loan's first installment due date, *when* the operation runs for that date, *then* that loan's stored bucket reads CURRENT.
- **E12-S1-AC4** — *Given* the completed run, *when* the loan records are compared against their pre-run state, *then* no fee, penal interest or collections record was created.
