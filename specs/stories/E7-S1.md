## User Story
As an admin, I want to filter applications by status and product and override an AUTO_REJECT with a comment and reason code so that genuine exceptions can be granted on the record.

## Business Value
Gives the business a controlled exception path that leaves a complete audit trail instead of an off-system workaround.

## Description
The FR-10 admin console. Overriding an AUTO_REJECT appends a new decision_record rather than mutating the old one, per D5, and writes an audit_event carrying the comment, reason code, acting user id and timestamp. The override's reason code is resolved from the application's pinned policy version, per D6.

## Scope
**In:** Application list with status and product filters; AUTO_REJECT override capturing a comment and a reason code; Audit entry with comment, reason code, acting user id and timestamp
**Out:** must not update or delete the overridden decision_record row; must not accept a reason code absent from the application's pinned policy version; must not modify a disbursed loan or restructure it

## Acceptance Criteria
- **E7-S1-AC1** — *Given* applications across several statuses and products, *when* the list is filtered to one status and one product, *then* only the matching rows are returned.
- **E7-S1-AC2** — *Given* an application decided AUTO_REJECT, *when* an admin overrides it with a comment and a reason code, *then* a new decision_record is appended and the application's current decision is the override.
- **E7-S1-AC3** — *Given* that override, *when* the audit trail is read, *then* it contains an entry carrying the comment, the reason code, the acting user id and a timestamp.
- **E7-S1-AC4** — *Given* the reason code supplied with the override, *when* it is looked up, *then* it exists in the policy version pinned on the application.

### Operations
1. Define `override_decision(application_id, reason_code, comment, actor) -> UnderwritingDecision` in `backend/src/service/origination/override.py` (new): read the latest decision via `DecisionRepository.latest_for_application` (owned by E5-S2), reject with 409 when it is not `AUTO_REJECT` or when `reason_code` is not declared by the application's pinned policy version (via the pinned-version accessor from E2-S1), then call `DecisionRepository.insert` (owned by E5-S2) with `supersedes_id` set to the overridden record's id so the prior row is never updated or deleted, and finally call `identity.audit` (owned by E1-S2) to write one `audit_event` carrying the comment, reason code, acting user id and timestamp.
2. Define `POST /applications/{application_id}/override` in `backend/src/api/origination/override_routes.py` (new): enforce `require_roles(ADMIN)` (owned by E1-S2), parse `{ reason_code, comment }`, call `override_decision`, and return the resulting `UnderwritingDecision` with its `supersedes_id`.
3. Register `override_routes.router` in the app factory `backend/src/api/app.py` (owned by E15-S1) via one `include_router` call.
4. Append one row to the read-heavy endpoint registry `backend/tests/slo/registry.py` (owned by E15-S3) for `GET /applications` and `POST /applications/{application_id}/override` so the list and override surfaces are covered by the SLO harness.
5. Add `getApplications(filters)` and `postOverride(applicationId, body)` functions to the application API client in `frontend/src/api/admin.ts` (new), calling the shared HTTP client from `frontend/src/api/client.ts` (owned by E1-S1).
6. Define the `AdminApplications` screen in `frontend/src/ui/pages/AdminApplications.tsx` (new): a status-and-product filtered application list, and an override action on an `AUTO_REJECT` row that submits a reason code and comment and re-renders the application's current decision as the override.
7. Add one route entry for `AdminApplications` to the frontend route registry `frontend/src/ui/routes.tsx` (owned by E1-S1).
8. Add integration tests in `backend/tests/integration/test_override_audit.py` (new) covering AC1-AC4: filtered listing (AC1), the appended superseding decision record (AC2), the audit entry's comment/reason code/actor/timestamp (AC3), and the 409 when the reason code is absent from the pinned policy version (AC4).
