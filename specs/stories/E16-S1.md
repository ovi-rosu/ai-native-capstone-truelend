## User Story
As an architecture reviewer, I want every named invariant to have a test and every production commit to carry agent provenance so that the capstone's structural claims are checkable rather than narrated.

## Business Value
Converts the architecture rules and the no-manual-coding constraint from prose into a suite that fails when either is broken.

## Description
Registers the named invariants — policy-version immutability, the EMI principal/rate/tenure invariant, and the six-layer one-way dependency rule — and fails the suite when a registered invariant has no test. Also records the D7 and D23 governance control: NFR-11 has no product story, and the pre-commit gate set plus the /gate attestation record is its evidence.

## Scope
**In:** Invariant registry and orphan-detection assertion; One or more tests per registered invariant; Provenance check over branch commits and the attestation record
**Out:** must not loosen an invariant's assertion to make a failing test pass; must not implement product behavior — this story adds no loan-platform capability; must not remove or weaken a pre-commit gate to clear the provenance check

## Acceptance Criteria
- **E16-S1-AC1** — *Given* a registry naming policy-version immutability, the EMI principal/rate/tenure invariant and the six-layer one-way dependency rule, *when* the architecture suite runs, *then* at least one test exists and executes for every registered invariant.
- **E16-S1-AC2** — *Given* a registered invariant with no corresponding test, *when* the architecture suite runs, *then* the suite fails and names the orphaned invariant.
- **E16-S1-AC3** — *Given* every production commit on the branch, *when* the provenance check inspects them, *then* each carries agent co-authorship and a passing record from the standard pre-commit gate set.
- **E16-S1-AC4** — *Given* the /gate attestation record, *when* it is read for the head commit, *then* it is present and records 0 hand-written production lines as the NFR-11 evidence.
