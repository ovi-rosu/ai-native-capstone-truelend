## User Story
As an authorised policy owner, I want to change a product's thresholds in the UI and have the new rules take effect immediately so that the business can tune products without a deployment.

## Business Value
Removes the engineering release from the product-tuning loop, which is the FR-13 no-code-change promise.

## Description
The Policy Editor over income, age, score, tenure and rate thresholds. Saving appends a new immutable policy version that becomes active in the running process, leaving the prior version byte-identical. Combined with the D6 submission-time pinning rule, an activation mid-flight never changes an in-flight application's basis.

## Scope
**In:** Policy Editor screen for the five threshold families; Versioned save endpoint that appends and activates; Hot activation with no process restart
**Out:** must not mutate or delete a prior policy version row; must not change the policy_version_id already pinned on a submitted application; must not expose the editor to a CUSTOMER session

## Acceptance Criteria
- **E3-S2-AC1** — *Given* an authorised user editing a product's income, age, score, tenure and rate thresholds, *when* the editor form is saved, *then* a new policy version row is appended and becomes the product's active version.
- **E3-S2-AC2** — *Given* the policy version that was active before the save, *when* it is re-read afterwards, *then* its stored values are byte-identical to their pre-save state.
- **E3-S2-AC3** — *Given* the newly activated policy version, *when* a subsequent application is decided in the same running process, *then* the decision cites the new policy version id with no process restart.
- **E3-S2-AC4** — *Given* a CUSTOMER session, *when* the Policy Editor save endpoint is called with it, *then* the response is 403 and no policy version row is appended.

### Operations
1. Define `publish_policy_version(product_code: str, rules: PolicyRules, actor: User) -> PolicyVersion` in `backend/src/service/policy/policy_publisher.py` (new): validate the incoming payload with `PolicyRules.model_validate` (owned by E2-S1, D-A), then call `PolicyVersionRepository.insert` followed by `PolicyVersionRepository.activate` (both owned by E3-S1) inside one database transaction so append-and-activate cannot partially apply, then call `identity.audit` (owned by E1-S2) to record the publish; the prior active version's row is never written to, leaving it byte-identical (AC2).
2. Define `POST /products/{product_code}/policy-versions` in `backend/src/api/policy/policy_version_routes.py` (new): guard it with `require_roles(ADMIN)` (imported from `backend/src/api/authz.py`, owned by E1-S2) so a CUSTOMER session receives 403 with no row appended (AC4); parse the request body into `PolicyRules`, call `policy_publisher.publish_policy_version`, and return 201 with the new `PolicyVersion` (`id`, `product_code`, `version_number`, `rules`, `created_by`, `created_at`, `is_active: true`) (AC1, AC3); append one `include_router` call to the app factory router registry in `backend/src/api/app.py` (owned by E15-S1).
3. Define `getProduct(product_code)` and `publishPolicyVersion(product_code, rules)` in `frontend/src/api/policy.ts` (new), calling `GET /products/{product_code}` and the endpoint from step 2 through the shared HTTP client (`frontend/src/api/client.ts`, owned by E1-S1) and formatting money fields with `formatMoney`/`parseMoney` (owned by E9-S1).
4. Define the `PolicyEditor` screen in `frontend/src/ui/pages/PolicyEditor.tsx` (new), per the `specs/design/mockups/E3-S2.html` mockup: product tabs for PERSONAL, VEHICLE and EDUCATION; a threshold form for the five families (`min_income`, `min_age`/`max_age`, `min_credit_score`, `min_tenure_months`/`max_tenure_months`, `annual_rate_pct`) plus editable reason-code and required-document lists; a read-only version-history table showing prior versions as byte-identical and non-editable; and a Save action that calls `policy.publishPolicyVersion` from step 3 and displays the newly activated version id/number on success. Add one route entry, restricted to the ADMIN role, to the frontend route registry (owned by E1-S1).
5. Add `backend/tests/integration/test_policy_activation.py` (new) covering: saving the editor form appends a new version that becomes the product's active version (AC1); the pre-save active version's stored `rules` are byte-identical when re-read afterwards (AC2); a subsequent application decided in the same running process cites the new policy version id with no process restart (AC3); and a CUSTOMER session calling the save endpoint from step 2 gets 403 with no row appended (AC4) — covering AC1-AC4.
