## User Story
As an underwriting lead, I want every monetary amount held in fixed-point decimal so that EMI and outstanding-principal figures never drift by rounding error.

## Business Value
Protects the AC-07 schedule invariants at their source, so no downstream story has to compensate for float drift in loan balances.

## Description
Publishes the Money value type and the fixed-point arithmetic helpers the policy, schedule and repayment stories consume — backend decimal.Decimal quantized to 2 places, frontend a decimal-library value that is never a float. This is the interface-layer artifact behind the contract edges from E3-S1, E1-S1 and E9-S3, per the D13 criterion.

## Scope
**In:** Money value type with 2-decimal quantization and arithmetic helpers; Static check reporting float arithmetic in money code paths; Frontend integer-minor-unit money module
**Out:** must not introduce a second currency or a currency-conversion path; must not expose a float-typed money field on any API contract; must not embed interest or EMI business rules in the type

## Acceptance Criteria
- **E9-S1-AC1** — *Given* randomly generated principal, rate and tenure triples, *when* a schedule is computed from each triple, *then* every money field on the result is a Decimal quantized to exactly 2 decimal places.
- **E9-S1-AC2** — *Given* the backend money code paths, *when* the static arithmetic check runs over them, *then* it reports 0 float arithmetic operations in those paths.
- **E9-S1-AC3** — *Given* the frontend money module, *when* a monetary amount is carried and formatted, *then* the value is held as a decimal value and never a float, and the static check reports 0 float arithmetic operations in that module.

### Operations
1. Define the `Money` value type in `backend/src/types/money.py` (new): wraps `decimal.Decimal`, quantizes to exactly 2 places on construction, and exposes `add`/`subtract`/`multiply`-style helpers that never touch `float`.
2. Define the Pydantic serializer that emits `Money` as a quoted 2dp JSON string in `backend/src/api/serializers.py` (new) — the single module holding this conversion per the D-G coupling risk.
3. Add a static/architecture check in `backend/tests/architecture/test_no_float_money.py` (new) that scans the backend money code paths (`backend/src/types/money.py`, `backend/src/api/serializers.py`) and asserts 0 float arithmetic operations.
4. Scaffold the minimum frontend project needed to run these files: `frontend/package.json`, `frontend/tsconfig.json`, `frontend/vite.config.ts`, `frontend/vitest.config.ts` (all new) with `decimal.js` as a dependency per D-G/D-J.
5. Define the frontend `Money` module in `frontend/src/types/money.ts` (new): wraps `decimal.js`, parses the quoted 2dp wire string, never converts to integer minor units, and never uses `number` arithmetic on the value.
6. Define `MoneyText` in `frontend/src/ui/components/MoneyText.tsx` (new): a display component that formats a `Money` value for presentation.
7. Add frontend unit tests in `frontend/tests/unit/money.test.ts` (new) covering AC3 (decimal-held, never-float) and a static grep-based check for float arithmetic in the money module.
