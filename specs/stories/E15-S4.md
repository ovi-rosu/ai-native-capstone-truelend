## User Story
As a platform operator, I want the metrics endpoint to expose request duration and to be unforgeable, so that the declared runtime SLO is measurable and an unauthenticated caller cannot rewrite the observability data plane.

## Business Value
`project-manifest.json` declares a p95 of 500 ms and E15-S3 registers a load harness against it, but with counters alone `slo.p95_ms` is always null — the target is asserted and unmeasurable. Separately, the `/gate` review of group A found that a crafted request path forged counter series, which drove this project's own SLO sensor to report a 99.90% error rate against a 1% budget and could equally mask a real outage.

## Description
Deepens E15-S1's observability surface rather than re-opening it. Carried as a separate story because E15-S1 is the first story in the matrix: adding acceptance criteria there renumbers every later VM id and invalidates all 13 frozen sprint contracts, which would make a frozen check report PASS for a criterion it no longer tests. Appended last, this story's criteria take new ids and every existing contract stays valid. See the AC-RENUMBERING note in `claude-progress.txt`.

## Scope
**In:** a request-duration histogram on GET /metrics labelled by method and route template; escaping and cardinality bounds for every exposition label; single-line, control-character-free rendering for log records and metrics lines
**Out:** must not add authentication to /metrics (that needs an api-contracts.md amendment and an auth layer that arrives with E1-S1); must not change the /health contract; must not introduce an external metrics backend or client library

## Acceptance Criteria
- **E15-S4-AC1** — *Given* the observability endpoint after at least one request has been served, *when* GET /metrics is scraped, *then* it exposes a request-duration histogram labelled by method and route template from which p95 can be computed, so the runtime SLO of 500 ms declared in project-manifest.json is measurable rather than always null.
- **E15-S4-AC2** — *Given* attacker-supplied text containing newlines, quotes and control characters reaching a log call or a metrics label, *when* the record or the exposition line is rendered, *then* the output is exactly one line per record with no raw control character and no injected series, so hostile input cannot forge a log entry or a counter.

### Entities

### Operations
1. Record request duration alongside the existing RED counters in `backend/src/api/middleware.py` (owned by E15-S1, existing, authorised by the Modifies row for this pair): measure with `time.perf_counter()` around the downstream call and accumulate into fixed latency buckets keyed by (method, route template), reusing `route_label(scope)` so the histogram inherits the same bounded cardinality as the counters.
2. Render the histogram in the exposition output in `backend/src/api/platform/routes.py` (owned by E15-S1, existing, same Modifies row): emit `http_request_duration_seconds_bucket` with a `le` label per bucket plus `_count` and `_sum`, each label value passed through the existing `_escape_label`, so p95 is computable by a scraper — covers AC1.
3. Add `backend/tests/architecture/test_observability_contract.py` (new): assert the histogram is present with method and route-template labels and that p95 is computable from the buckets (AC1); assert a crafted percent-encoded path cannot inject a series and that unrouted paths collapse to one label value (AC2); assert a log record carrying newlines, quotes and control characters renders as exactly one line with no raw control character (AC2).
