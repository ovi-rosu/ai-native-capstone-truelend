## User Story
As a reviewer, I want the whole platform to come up from a clean checkout with one command so that I can evaluate it without bespoke setup.

## Business Value
Makes the capstone reproducible for graders and keeps the six-layer architecture rule mechanically enforced rather than aspirational.

## Description
Defines the self-hosted stack NFR-12 names — a single Postgres, the Python 3.12 FastAPI backend and the TypeScript React-Vite frontend — with compose readiness gated on the /health probe from E15-S1. Also lands the architecture test that asserts the one-way dependency direction across Types, Config, Repository, Service, API and UI.

## Scope
**In:** docker-compose.yml with exactly three services and healthchecks; Dockerfiles for backend and frontend; Layer-dependency architecture test over the six layers
**Out:** must not add a second database engine, cache or message broker; must not configure any external provider endpoint or live credential; must not relax the one-way layer rule to make an existing import pass

## Acceptance Criteria
- **E15-S2-AC1** — *Given* a clean checkout with no prior containers, *when* docker compose up runs to completion, *then* exactly one Postgres service, the Python 3.12 FastAPI backend and the TypeScript React-Vite frontend are running and all three report healthy.
- **E15-S2-AC2** — *Given* the running stack, *when* the layer-dependency architecture test executes, *then* it reports 0 violations of the one-way rule across Types, Config, Repository, Service, API and UI.
- **E15-S2-AC3** — *Given* the compose service inventory, *when* it is asserted against the declared stack, *then* no second database engine and no external provider endpoint is configured.

### Operations
1. Verify and, if needed, update the `architecture` block in `project-manifest.json` (layers `types, config, repository, service, api, ui`; `layer_roots` `backend/src` and `frontend/src`; the five bounded-context roots) so it matches the layout this story builds — without this block the layer-dependency test matches no file and passes vacuously.
2. Define the one-way layer-dependency architecture test in `backend/tests/architecture/test_layer_dependencies.py` (new): read `project-manifest.json`'s `architecture` block, walk every import under `backend/src` and `frontend/src`, and assert 0 violations of the Types → Config → Repository → Service → API → UI direction — covering E15-S2-AC2.
3. Add `Dockerfile.backend` (new): a Python 3.12 image that runs `uv sync` for the backend and starts `uvicorn src.api.app:app`, with a `HEALTHCHECK` that polls `GET /health` (from E15-S1).
4. Add `Dockerfile.frontend` (new): a Node build stage running `npm ci && npm run build` with `VITE_API_BASE_URL` as a build argument, then a minimal static-serve stage carrying its own `HEALTHCHECK`.
5. Add `docker-compose.yml` (new) declaring exactly three services — one `postgres` (no second database engine, cache or message broker), `backend` (built from `Dockerfile.backend`, health-gated on `GET /health`), and `frontend` (built from `Dockerfile.frontend`) — each with a `healthcheck` and no external provider endpoint or live credential configured.
6. Extend `init.sh` (existing bootstrap script) to: verify `docker` and `docker compose` are present, copy `.env.example` to `.env` and generate a local `JWT_SECRET` when absent, run `docker compose up -d --build`, poll `GET /health` until 200 or a bounded timeout, print the frontend URL, and exit non-zero if any of the three services never reports healthy — the exit code the E15-S2-AC1 smoke test depends on.
7. In `backend/tests/architecture/test_layer_dependencies.py` add a static-parse test over `docker-compose.yml` asserting exactly one `postgres`, one `backend` and one `frontend` service are declared each with a `healthcheck`, and a second test asserting the compose service inventory names no second database engine, cache, message broker or external provider endpoint — together covering E15-S2-AC1 (the static half; `init.sh`'s exit code is the runtime half) and E15-S2-AC3, alongside the layer test from step 2 for AC2.
