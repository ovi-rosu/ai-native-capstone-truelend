## User Story
As a compliance officer, I want every underwriter and admin route guarded at the controller and every privileged action audited so that role separation is provable rather than assumed.

## Business Value
Makes the NFR-04 100%-of-routes claim self-maintaining: a newly added unguarded route fails the suite instead of shipping.

## Description
Deepens E1-S1 into the full role boundary: exactly one of CUSTOMER, UNDERWRITER or ADMIN per user, 401 with no session, 403 on the wrong role, and an audit_event append for every privileged action. The authorization suite enumerates routes from the OpenAPI schema rather than a hand-written list, per D16.

## Scope
**In:** Controller-layer authorization dependency applied to underwriter and admin routes; Schema-driven authorization test that asserts 100% route coverage; Append-only audit_event write carrying acting user id and timestamp
**Out:** must not move the authorization check below the controller layer; must not allow a user to hold more than one role; must not update or delete an existing audit_event row

## Acceptance Criteria
- **E1-S2-AC1** — *Given* any underwriter or admin route, *when* it is called with no session, *then* the response is 401 and no handler body executes.
- **E1-S2-AC2** — *Given* a CUSTOMER session, *when* an underwriter or admin route is called with it, *then* the response is 403, while each role reaches its own surfaces with 200.
- **E1-S2-AC3** — *Given* the underwriter and admin routes enumerated from the OpenAPI schema, *when* the generated authorization suite runs, *then* it reports 100% of those routes covered by both the no-session and wrong-role cases and fails when a new route is unguarded.
- **E1-S2-AC4** — *Given* an authenticated underwriter or admin action, *when* the action completes, *then* an audit_event row exists carrying the acting user id and a timestamp.
